# COZE：Kiikis 2.1 分阶段独立验证说明

## 每次新验证只加载这些文件

1. `docs/kiikis-2.1/KIIKIS-2.1-总PRD-v1.0.md`
2. 当前 COZE 阶段文件
3. TRAE 当前阶段交接与证据

不要读取其他阶段执行文件，不要依赖聊天中的“已经完成”。

## 验证者职责

COZE 是独立质量门禁，不是 TRAE 的总结 Agent。验证顺序：

1. 确认 commit、部署环境和 feature flags。
2. 复跑自动化测试并保存原始输出。
3. 用浏览器按真实用户旅程操作。
4. 用第二账号、匿名账号或审核员验证权限负例。
5. 查数据库/API 事实，区分页面展示、fixture、代码存在和真实连接。
6. 对 P0/P1 给出逐项 PASS/FAIL 和证据链接。

## 统一判定

- `PASS`：当前阶段所有 P0/P1 通过，证据齐全，无 fixture 冒充真实能力。
- `CONDITIONAL PASS`：只剩不阻断的 P2 或文案；必须写 owner、截止时间和风险。
- `FAIL`：任一 P0/P1 失败、无法复现、测试被跳过、数据来源不明、权限/支付/审核证据缺失。

构建成功不能替代用户旅程；截图不能替代权限负例；fixture 不能替代真实 API。

## 缺陷规则

- P0：数据丢失、越权、支付错误、核心旅程阻断、公开社区无治理、无法回滚。
- P1：关键功能不完整、主流视口不可用、错误恢复失败、状态误导。
- P2：不阻断的文案、微小视觉或低频体验问题。

只要 P0/P1 未关闭，不允许建议进入下一阶段。
