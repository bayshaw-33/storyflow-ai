# TRAE：Kiikis 2.1 分阶段执行说明

## 每次新任务只加载这些文件

1. `docs/kiikis-2.1/KIIKIS-2.1-总PRD-v1.0.md`
2. 当前阶段文件
3. 上一阶段的交接记录（Phase 0 没有上一阶段）

不要一次性读取本目录其他阶段文件。当前阶段外的需求只记录到交接，不实现。

## 阶段执行协议

1. `git status --short --branch`，确认用户现有改动并记录基线 commit。
2. 为当前阶段建立独立分支或 worktree；不得复用残留修改。
3. 先写回归测试并运行，必须看到因目标行为缺失而失败。
4. 只实现让当前阶段验收通过的最小变更。
5. 依次运行阶段测试、`npx tsc --noEmit`、`pnpm build`。
6. 浏览器手工验证真实路由与错误态；fixture 只能辅助，不替代真实链路。
7. 单独 commit，输出标准交接，不自行进入下一阶段。

## 完成声明规则

以下任一情况存在时不得写“完成”：

- 测试未实际运行或只看静态代码；
- 只在 fixture 模式通过；
- 数据库 migration 未核验或 RLS 未测试；
- 点击行为没有确认最终 URL 和页面对象；
- 支付只验证 success URL，没有 webhook 证据；
- 社区上线但举报、屏蔽、审核、恢复未跑通；
- 有 P0/P1 失败被标记为“已知问题”。

## 提交粒度

每个阶段至少包含一个独立 commit。阶段内部如果跨数据库、服务端和 UI，建议按：

```text
contract/test → migration/server → client/UI → integration/e2e
```

拆成可回滚提交，但不得把下一阶段混入。
