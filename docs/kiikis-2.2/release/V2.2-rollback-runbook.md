# KIIKIS V2.2 回滚 Runbook

> **原则**：回滚 Web release 和关闭入口；**永不回滚 forward migration**。
> V2.2 数据与旧 UI 兼容：旧项目仍可读，V2.2 Work/Source 数据保持安全。

## 回滚级别

### L1：关闭 V2.2 入口（最快，秒级）

```bash
# 设置 KIIKIS22_FF_ENTRIES_ENABLED=false（Vercel 环境变量）
# 前端 fail-closed：入口立即隐藏，旧入口（project-start 等）恢复主导
```

- 影响：用户回到旧 UI/旧入口；V2.2 数据不删除、不损坏
- 风险：无（纯入口可见性控制）

### L2：回滚 Web release（分钟级）

```bash
# Vercel：Redeploy 上一个 Ready 生产部署
vercel ls storyflow-ai            # 找上一个 ● Ready 的 Production 部署
vercel promote <deployment-url>   # 或 Dashboard → Production Deployments → Promote
```

- 影响：Web 回到上一稳定版本；DB 保持 V2.2 schema（不回滚 migration）
- 注意：旧代码读取新表 = 安全（V2.2 只新增可选字段/新路由）；若旧代码对未知列报错，优先 L1 + L3 组合

### L3：数据保护（不动 migration）

- append-only 表（versions/links/decisions/events/messages/snapshots/candidates）**绝不 UPDATE/DELETE**
- 需要"修正"数据时：新增修正 migration（forward-only），保留错误行 + evidence
- 检查 RLS：确认所有 K22 表仍 ENABLE ROW LEVEL SECURITY

## 回滚顺序（发布停线时）

1. **L1**：关入口（`KIIKIS22_FF_ENTRIES_ENABLED=false`）
2. **L2**：promote 上一 Ready 部署
3. **验证**：
   - 旧 UI 可继续读 Project（resolve-work 适配仍工作）
   - V2.2 Work/Source/Universe 数据在 DB 中完好
   - `pnpm audit:kiikis22` 仍全绿（代码回滚后重新跑）
4. **记录**：回滚时间、原因、影响面、evidence（走 `storyflow_evidence_events`，append-only）

## 禁止

- ❌ 不执行破坏性数据库回滚（DROP TABLE / 批量 DELETE）
- ❌ 不修改 Phase 0–5 migration 文件
- ❌ 不回滚已发布的 forward migration

## 回滚后恢复

- 缺陷修复后以新版本（新 migration + 新部署）重新发布，不"重放"旧版本
- 灰度从内部账号重新开始
