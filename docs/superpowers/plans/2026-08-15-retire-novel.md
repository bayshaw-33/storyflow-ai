# 退役小说入口与精确清理小说数据

## 目标

- 从 Kiikis 的用户可达入口、工作流配置、Universe 创建入口和新契约中移除小说。
- 旧小说项目作为废弃数据，不再出现在项目列表、Universe 作品列表、任务中心或可进入的工作台中。
- 仅删除带有明确小说标记的数据；保留所有其他工作流项目、Universe、资产、创作记录和账号数据。
- 将脚本入口统一导向当前三栏剧本创作台，不再通过 `/novel-workbench` 承载剧本。
- 将 `origin/main` 发布为 `kiikis.com` 的最新前端版本，并在部署后核验线上静态资源已更新。

## 约束与判定规则

- 不修改历史 migration；新增带有明确日期和用途的退役 migration。
- 不使用“删除全部项目”或按模糊文本匹配的 SQL。
- 数据清理前先在 staging 读取表结构、外键和现存小说标记，形成可核对的数量快照。
- 数据清理只允许命中以下可验证条件之一：结构化 `workflow_type/content_type/work_type=document_type = 'novel'`，或项目 JSON 中明确的 `workflowType/contentType/workType = 'novel'`。
- 清理后对同一批表执行残留断言；若仍有小说标记，migration 失败。
- 不在本阶段直接对生产 Supabase 执行 destructive SQL；先应用到 staging 并验证，生产执行前单独确认目标。

## 实施步骤

### 1. 建立回归测试

- [ ] 扩展 `tests/screenplay-entry-routing.test.mjs`，断言旧路由不再生成小说入口，现有项目进入 `/script-workbench?projectId=...`。
- [ ] 为工作流入口、模板、Universe 创建配置和 V2 工作流类型增加“无 novel 配置”的静态回归断言。
- [ ] 为项目/任务读取路径增加小说过滤测试，确保小说记录被隐藏、非小说记录原样保留。
- [ ] 先运行相关 Node 测试，确认测试在实现前能捕获旧行为。

### 2. 退役用户可见入口与配置

- [ ] 删除工作流模块、模板、Universe 创建选项和页面文案中的小说入口。
- [ ] 将脚本旧入口和旧项目跳转统一解析到三栏剧本创作台；不再把 screenplay 当作 novel-workbench 的 mode。
- [ ] 保留 `/novel-workbench` 的不可达兼容路由或改为安全重定向，避免旧书签进入旧创作台；不得继续渲染小说配置。
- [ ] 从新契约和 dashboard/job fixture 中移除 novel 作为可选工作流；不影响已有非小说类型。
- [ ] 删除/停用与入口直接相关的小说配置和标签；对仅用于历史兼容、且没有用户可达路径的底层类型不做无关大规模重构。

### 3. 屏蔽旧小说项目与任务

- [ ] 在 Supabase 项目读取/合并层过滤结构化标记为 novel 的项目，确保旧数据不进入首页、项目列表、Universe 作品或工作台解析。
- [ ] 在任务中心和 dashboard 数据适配层过滤明确属于小说的旧任务，保留其他任务的状态、取消和详情行为。
- [ ] 对项目 JSON 仅读取明确字段判断，不用标题、描述或全文搜索误伤其他项目。
- [ ] 更新相关 fixtures 和 UI 测试，覆盖“小说隐藏、剧本仍可进入、其他类型不受影响”。

### 4. 设计并加入精确数据库清理 migration

- [ ] 在 staging 查询实际存在的项目、作品、版本、文档、任务、证据和关联表，以及外键级联关系。
- [ ] 记录每张目标表清理前的小说行数，并确认非小说行数作为保护基线。
- [ ] 新增 migration：按已验证的结构化字段和明确 JSON 字段删除小说记录；先删子表，再删父表，或依赖已验证的级联关系。
- [ ] 更新仍允许 novel 的活动约束/默认值，使新写入无法再次产生小说；不改历史 migration 文件。
- [ ] migration 末尾增加残留检查，并增加非小说保护检查，防止清理范围扩大。
- [ ] 不删除 auth 用户、Universe、资产、歌曲、剧本、视频、配音、剪辑或其他非小说项目数据。

### 5. Staging 验证

- [ ] 在临时 worktree 连接 staging，应用 migration 并记录清理前后计数。
- [ ] 运行 Node 回归测试、V2 相关服务测试、TypeScript 检查和生产构建。
- [ ] 对 staging 做最小冒烟：打开工作流入口、创建/进入剧本项目、检查 Universe 作品列表和任务中心。
- [ ] 验证 staging 上非小说项目、Universe、资产和任务仍存在且可读。
- [ ] 若 migration 或测试失败，先修复并重复验证，不执行生产清理。

### 6. 提交与交接

- [ ] 在功能分支提交代码、测试、migration 和计划/交接记录。
- [ ] 合并到 `main` 前复核 `git diff`，确认没有误删共享文件或非小说数据逻辑。
- [ ] 合并并推送后回报 commit、验证命令、staging 清理计数和明确的生产执行状态。

### 7. 线上前端发布核验

- [ ] 合并前确认 `main` 包含当前 V2.2 剧本工作台和本次小说退役改动。
- [ ] 推送 `main` 触发线上部署，不直接改动 Vercel 或生产数据库配置。
- [ ] 通过 `kiikis.com` 的页面和静态资源核验：新项目入口、剧本入口、旧项目进入剧本台、Universe 作品入口均来自最新版本；页面不再提供小说模块。
- [ ] 若线上仍返回旧构建，检查部署状态/缓存并报告具体阻塞，不宣称已更新。

## 验证命令

```bash
node --test tests/screenplay-entry-routing.test.mjs
node --test tests/creation-workbench-ui.test.mjs
npx tsc --noEmit
pnpm build
```

数据库验证必须额外输出：

```text
目标表：小说清理前数量 -> 清理后数量
保护表/非小说基线：清理前数量 -> 清理后数量
残留小说标记：0
```
