# 音乐工作台生成历史隔离与删除设计

## 已确认目标

- 生成历史只展示当前音乐项目的音频任务。
- 新建项目或尚未取得项目 ID 时不加载任何旧项目历史。
- 用户可以删除当前项目中的单条生成历史。
- 删除操作必须校验登录用户和项目归属，并清理已入库的音频文件及对应音频资产记录。
- 删除前由界面二次确认；删除失败时保留历史卡片并显示可读错误。

## 根因

音乐工作台初始化时调用 `/api/audio/jobs` 只携带用户会话，没有携带 `projectId`；服务端列表查询也只按 `owner_id` 和 `job_type` 过滤。因此同一账号下其他项目的音乐任务会进入当前工作台。

## 方案

1. 工作台只有在 `songProjectId` 存在时请求 `/api/audio/jobs?projectId=<id>`；无项目 ID 时清空并保持空历史。
2. 服务端列表接口支持 `projectId` 过滤，并把 `project_id` 写入返回任务。
3. `/api/audio/jobs/[jobId]` 增加 DELETE：按任务 ID、当前用户和当前项目读取目标，删除 `audio-assets` 中的存储对象、对应 `storyflow_assets` 音频记录和生成任务。
4. 删除按钮放在每条历史卡片操作区，使用确认对话框；删除成功从当前列表移除并在播放器选中项变化时安全回退。
5. 保留 `SongLibraryClient` 的全账号作品库查询能力；只有音乐工作台历史入口强制项目隔离。

## 验收

- 跨项目任务不会出现在当前工作台。
- 新建项目不会短暂显示旧任务。
- 删除当前项目任务后，刷新页面仍不再出现该任务，音频存储对象同步清理。
- 其他用户或其他项目的任务删除请求返回 404/403，不会被改动。
- 删除、项目过滤、播放器回退和页面行为均有自动化测试覆盖。
