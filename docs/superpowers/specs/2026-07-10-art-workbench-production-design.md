# Kiikis 美术工作台生产版设计规格

日期：2026-07-10  
状态：待最终书面确认  
负责人：Kiikis 创作负责人

## 1. 目标

将现有 `/art-workbench` 从本地原型升级为 Kiikis 的正式影视美术生产工具。用户可以上传剧本、项目背景、角色圣经和图片资料，或关联已有 Universe 项目；AI 自动拆解角色、场景和关键道具，并允许用户通过对话和详情编辑器完成增删、修改、生成、上传、定稿、版本管理及下游交付。

第一阶段交付必须形成真实闭环：

1. 新建项目或关联已有项目。
2. 上传和解析资料，保留来源与解析记录。
3. AI 拆解角色、场景、关键道具为草稿资产。
4. 通过聊天或详情页编辑美术仓库。
5. 通过 FLUX 或 Atlas Cloud 生成和修改图片。
6. 用户上传外部生成图片作为候选或母版。
7. 设置终稿并发布到关联 Universe。
8. 分镜和视频工作台引用明确的资产版本。
9. 全流程保存操作者、时间、输入、模型和版本留痕。

## 2. 已确认的产品原则

- 工作台主页采用双栏结构：左侧 AI 对话区约占页面 `38%`，右侧美术仓库约占 `62%`。
- 不保留大面积资料正文预览。资料只在对话区顶部以紧凑附件和来源状态展示。
- 点击仓库资产卡进入独立详情页；详情页左侧为大图、候选版本和变体，右侧为编辑器与生成设置。
- 角色、场景和道具统一使用“母版 + 变体 + 版本”结构。
- 资产“设为终稿”与“发布到 Universe”是两个独立动作。
- Universe 是项目归属和下游交付核心，不降级为普通标签。
- 云端数据库和 Storage 是生产数据源，localStorage 只用于未提交输入或迁移兜底。
- 所有 API Key 仅保存在服务端或加密用户配置中，不进入前端、日志、导出或 Git。

## 3. 项目入口

用户进入美术工作台时必须选择：

### 3.1 新建项目

- 输入项目名称和必要基础信息。
- 同时创建 Universe 项目外壳，并建立美术项目与 Universe 的关联。
- 后续小说、剧本、分镜、视频可继续复用同一 Universe。

### 3.2 关联已有项目

- 从用户有权限的 Kiikis 项目或 Universe 中选择。
- 自动载入已有剧本、项目背景、角色圣经、角色卡和可用 canon 快照。
- 显示关联来源、同步状态和最近更新时间。

更换或解除项目关联属于高风险操作，必须二次确认并记录日志。

## 4. 页面结构

### 4.1 美术仓库主页

左侧 AI 对话区：

- 顶部：KK 美术助理、项目资料状态、管理资料入口。
- 中部：聊天记录、AI 变更结果、撤销和确认卡片。
- 底部：文本输入、文件上传、图片上传、Universe 引用和发送。
- 支持上传剧本、背景、角色圣经、表格和参考图片。

右侧美术仓库：

- 角色、场景、道具三类标签及数量。
- 状态筛选：草稿、生成中、待确认、已锁定、已发布、失败。
- 资产卡显示主图、名称、资产类型、变体数量、状态和来源。
- 支持搜索、筛选、排序和手动新增。

### 4.2 资产详情页

左侧：

- 当前母版或变体大图。
- 母版/变体切换。
- 候选版本缩略图、生成中状态、失败重试。
- 上传版本、下载原图、比较版本。

右侧：

- 名称、类型、叙事功能、设计说明和身份锚点。
- 正向提示词和模型适配参数。
- 供应商、模型、宽高比、分辨率、候选数量和种子。
- 生成新版本、基于当前图修改、设为终稿、发布到 Universe。
- 版本来源、创建者、生成时间和下游引用情况。

## 5. AI 对话控制

聊天不是单纯问答，而是美术仓库的自然语言命令层。

支持的第一阶段意图：

- 新增角色、场景、道具或变体。
- 修改名称、叙事功能、设计说明、提示词和状态。
- 上传图片并绑定已有资产。
- 上传图片并创建新资产或角色母版。
- 根据资料重新拆解或补充遗漏资产。
- 创建多个有关联的配角、场景或道具。
- 请求生成、修改、重试或创建相似版本。
- 查询未完成资产、待确认资产和发布状态。

示例：

- “这是女反派的形象，帮我增加角色并设为母版。”
- “再增加两个配角，他们是主角从小一起长大的发小。”
- “把这个场景改成暴雨夜，但不要覆盖白天母版。”

### 5.1 分级执行规则

直接执行并提供撤销：

- 新增草稿资产或变体。
- 修改普通文字字段。
- 绑定未锁定候选图片。

执行前必须确认：

- 删除资产或版本。
- 覆盖或解除已锁定终稿。
- 更换 Universe 关联。
- 发布、撤回或替换已被下游引用的版本。

当上传图片用途不明确时，AI 必须询问图片属于哪个资产或用途；当用户已经明确说明时直接执行。

AI 写操作必须使用结构化 action schema，由服务端校验权限和目标状态，不能让模型直接写数据库。

## 6. 资产模型

### 6.1 虚拟演员与项目角色

- 虚拟演员保存跨项目复用的固定脸部、身体比例和基础身份参考。
- 项目角色保存演员在具体作品中的角色名、身份、气质和剧中造型。
- 项目角色可从虚拟演员库选角，也可生成全新面孔。
- 全新角色定稿后可主动“保存为虚拟演员”，但不自动进入演员库。
- 项目妆造不反向覆盖演员母版。

### 6.2 角色

角色母版升级为“专业完整角色参考表”。母版锁定角色身份、脸部、身体比例、发型和基础气质；剧中造型保存妆容、服装、配饰及剧情状态。

默认参考表生成指令语义：

> 为已选定的角色母版图生成专业完整角色参考表。纯白色无缝背景，干净整洁网格布局。包含正面、3/4、侧面、背面全身体态转面图；主体身份与比例尺；6-8 色调色板；8 帧情绪进阶；5 帧微表情；多角度头部细节；中性站姿与姿态变化；一张特写；底部服装和配饰特写，包括头发质地、外套面料、鞋子和配饰；多种手势参考；角色轮廓指南。所有画面保持脸部、身体比例和身份一致。4:3 横版，布局对齐。

系统将用户口语中的“图1”解析为当前选中的母版或候选版本，不把“图1”作为无引用文本直接发送。

### 6.3 场景

- 场景母版固定空间结构、时代、材质、主色、灯光逻辑和关键陈设。
- 场景变体表示白天、夜晚、天气、损毁、节日布置等状态。

### 6.4 道具

- 道具母版固定造型、尺寸、材质和识别特征。
- 道具变体表示打开/关闭、完整/损坏、使用前/使用后等状态。

## 7. 图片生成与供应商

### 7.1 权限路由

普通账号：

- 使用 Kiikis 平台公用 Black Forest Labs FLUX API。

特殊授权账号（包括管理员）：

- `智能选择`：按任务从 Atlas Cloud 模型中路由，失败时可回退到 FLUX。
- `Atlas Cloud`：手动选择 Kiikis 允许的 Atlas 图片模型。
- `FLUX`：手动使用平台 FLUX。

未来：

- 用户可绑定自己的 Atlas Cloud、BFL 或其他图片 API Key。
- 自带 Key 与平台 Key 在权限、用量和账单记录中分离。

### 7.2 模型目录

不直接抓取 Atlas 网页模型列表。服务端维护经过验证的模型注册表，包含：

- 模型 ID、显示名和供应商。
- 文生图、图生图、多参考图、编辑能力。
- 支持的尺寸、宽高比、输出数量和特有参数。
- 推荐任务、可用状态和费用提示。

智能路由依据资产类型、任务类型、参考图数量、身份一致性要求和账号权限选择模型。

### 7.3 生成数量与版本

- 默认每次生成 1 张。
- 用户可选择 1、2、4 张候选。
- 每张候选独立保存模型、参数、提示词、种子、参考图、费用和操作者。
- 生成结果不自动覆盖终稿。
- 支持基于候选继续修改或生成相似版本。

### 7.4 图片持久化

供应商返回的临时 URL 不能作为长期资产地址。服务端在任务完成后立即下载结果并转存到 Supabase Storage，记录校验信息和原始供应商任务 ID。

## 8. 定稿、发布与下游引用

资产状态：

`draft → generating → candidate → approved → published → archived`

- `设为终稿` 将候选版本锁定为 approved，不自动写入 Universe。
- `发布到 Universe` 将 approved 版本发布给关联 Universe 和下游工作流。
- 已发布资产修改时创建新版本，不覆盖旧版本。
- 分镜和视频引用明确的 `asset_version_id`。
- 详情页显示该版本被哪些分镜或视频任务引用。
- Universe canon 更新仍遵循 Inbox/审核机制；美术资产发布不能静默改写角色 canon。

## 9. 云端数据与协作

生产数据保存在 Supabase：

- 项目、资料来源、聊天消息和 AI action。
- 资产、变体、版本、生成任务和发布记录。
- 文件、上传图片和生成原图保存至 Storage。
- 操作日志保存操作者、时间、前后状态和来源。

项目角色：

- owner/admin：管理成员、删除终稿、发布和撤回 Universe 资产。
- editor：创建和修改草稿、候选及普通字段。
- viewer：只读。

协作状态显示当前编辑者。第一阶段采用软锁和冲突提示，不实现复杂的多人同时编辑合并。

## 10. 建议数据边界

新增或扩展以下服务端实体，具体表名在实施计划中与现有 migration 对齐：

- `art_projects`
- `art_source_documents`
- `art_chat_messages`
- `art_actions`
- `art_assets`
- `art_asset_variants`
- `art_asset_versions`
- `art_generation_jobs`
- `art_publications`
- `art_audit_events`

所有项目表带 `user_id`、可选 `team_id`、`universe_id` 和时间字段；所有 RLS 复用现有团队 owner/admin/editor/viewer 权限语义。

## 11. 错误处理

- 文档解析失败：保留文件记录，显示失败原因并允许重试。
- AI 拆解格式错误：不覆盖已有仓库；保存原响应摘要并允许重试。
- 图片生成失败：候选槽进入失败状态，不影响其他版本。
- Atlas 失败：智能模式可回退 FLUX；手动 Atlas 模式提示失败，不静默更换模型。
- 供应商完成但 Storage 转存失败：任务标记为 `persist_failed`，后台重试，不能把临时 URL 当终稿。
- 权限变化或编辑冲突：拒绝写入并刷新最新版本。
- 发布失败：终稿仍保留为 approved，可重新发布。

## 12. 验收标准

1. 用户可新建项目并同步创建 Universe，或关联已有项目。
2. 用户可上传资料或从 Universe 载入资料，AI 生成角色、场景和道具草稿。
3. 左侧对话区可以通过自然语言新增、编辑和修改仓库资产。
4. 用户可在聊天中上传图片并创建角色或绑定母版。
5. 仓库主页与独立资产详情页符合已确认的 38/62 布局与大图/编辑器结构。
6. 角色、场景、道具均支持母版、变体和版本。
7. 普通账号可通过平台 FLUX 生成图片；特殊账号可智能或手动使用 Atlas/FLUX。
8. 每次可选择 1/2/4 张候选，结果转存 Supabase Storage。
9. 用户可设为终稿并单独发布到 Universe。
10. 分镜与视频可引用已发布的明确版本。
11. 团队成员按角色共享数据，所有重要操作有审计记录。
12. API Key 不出现在客户端 bundle、数据库明文字段、日志、导出或 Git。

## 13. 第一阶段范围外

- Photoshop 或剪映级像素编辑器。
- 实时多人光标和字段级 CRDT 合并。
- 自动训练 LoRA 或角色专属模型。
- 自动发布未经用户锁定的美术资产。
- 自动覆盖演员母版或 Universe canon。
- 无限制暴露 Atlas 全部模型和全部供应商参数。

## 14. 实施约束

- 保留现有 `/art-workbench` 入口，分阶段迁移其本地状态。
- 复用现有演员库、团队、Universe Inbox 和项目形象版本契约。
- Provider 层隔离 Atlas 和 BFL 参数差异。
- 先完成真实数据、API 和状态流转，再由前端协作者做视觉精修。
- 每个阶段必须更新 `docs/DEV_HANDOFF_LOG.md`，提交并推送 GitHub，并将最新代码同步到 SMB 工作目录。
