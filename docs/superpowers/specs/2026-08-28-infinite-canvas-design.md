# Kiikis 分镜无限画布导演板设计

日期：2026-08-28  
范围：Production Workbench 的“画布”第五子视图  
状态：待实现计划评审

## 1. 目标

将现有的有限自由排布画布升级为可持续使用的“无限画布导演板”，用于整理分镜、场次、提示词思路和导演备注，同时保持现有制作工作台的统一界面与现有项目数据不变。

成功标准：

- 画布可以连续平移、缩放，镜头不受固定边界限制。
- 镜头仍然从现有 `scenes`/`frames` 实时读取，不复制剧本或分镜正文。
- 旧项目中的 `shots`、`notes`、`viewport` 数据可直接读取，打开后不丢布局。
- 所有变化继续沿用现有 `ProductionWorkbench` 草稿保存链路，不新增数据库表或 migration。
- 画布仍是分镜统一工作台中的一个子视图，不新增顶部工作台、不隐藏全局导航。

## 2. 不做什么

- 本阶段不把画布升级为 Universe 全域创作板；Universe 节点只预留扩展接口。
- 不改变 `ProductionProjectState` 的数据库存储位置、草稿接口、项目路由和制作工作台布局。
- 不引入重型画布依赖（React Flow、tldraw、Konva 等），避免 bundle 增长、交互风格改变和数据迁移风险。
- 不让 AI 直接修改剧本正文、分镜正文或定稿；AI 相关能力只生成建议，需用户确认。

## 3. 产品形态

### 3.1 画布定位

画布是导演的空间化工作板：镜头卡片是主要对象，便签用于导演意图、调度、连续性和待办，分组/连线用于表达场次结构与视觉关系。画布布局是辅助信息，不成为剧本和分镜内容的第二份事实来源。

### 3.2 现有布局保持不变

- 保留 `UnifiedStoryboardStage` 中现有“画布”子视图。
- 保留右上方轻量工具栏，不新增巨大的页头或第三栏。
- 工具栏只显示高频操作：添加镜头、全部镜头、添加便签、适配视图、缩放、撤销/重做（如现有草稿历史能力允许）。
- 解释性长文案改为短提示或 tooltip，避免挤压工作区。

## 4. 交互设计

### 4.1 无限视口

- 世界坐标不依赖画布容器尺寸；视口只保存平移和缩放。
- 空白处拖拽平移；按住空格拖拽也可平移；中键拖拽兼容鼠标操作。
- 滚轮/触控板缩放，缩放中心跟随指针位置，避免用户缩放后丢失目标。
- 缩放范围扩展为 10%–400%，仍通过统一的 `clampZoom` 保护异常值。
- “适配视图”计算所有镜头、便签和分组的包围盒，将内容放入可见区域；空画布回到默认视口。
- 所有交互只改变 `viewport` 或画布布局字段，不改变分镜内容。

### 4.2 选择与整理

- 点击选择单个镜头/便签，`Shift` 点击追加选择。
- 空白处拖拽框选；`Esc` 清空选择；`Delete/Backspace` 移除选中画布对象，不删除原始镜头。
- 选中对象显示轻量边框和上下文工具条。
- 支持移动、多选移动、复制便签、对齐/等距排列。
- 镜头卡提供“打开镜头”入口，回到现有分镜详情/提示词区域；删除操作文案明确为“移出画布”，避免误解为删除项目数据。

### 4.3 导演对象

首版对象：

- 镜头卡：只存 `shotId` 和布局元数据，标题、场次、帧图、提示词实时读取现有分镜数据。
- 便签：存文本、颜色和位置，可编辑。
- 分组框：存标题、颜色、位置、尺寸和成员引用，用于场次/段落/视觉风格分组。
- 连线：存两个画布对象引用、方向和样式，用于表达镜头顺序、视线、因果或转场关系。

对象能力必须保持可读：镜头删除后显示“镜头已删除”的失效卡片；失效引用可以清理，但不能静默删除其它对象或原始数据。

### 4.4 自动排版

提供三个确定性排版入口：

- 按场次：按场次分组、组内按镜头顺序排列。
- 按镜头顺序：按 `scene.order`/`shot.order` 排成导演检查流。
- 整理当前选择：只对选中对象执行网格或横向/纵向排列。

自动排版只写入布局坐标和分组信息，执行前保留一次可撤销快照；不会覆盖便签正文。

### 4.5 导出

首版提供：

- 导出画布快照 PNG，用于导演沟通和参考。
- 导出布局 JSON，用于备份布局、排查数据和未来 Universe 画布迁移。

导出内容必须标注这是“画布布局/导演备注”，不冒充分镜定稿或法律证据。正式分镜和创作留痕仍走现有工作台导出能力。

## 5. 数据兼容策略

继续使用现有 `ProductionProjectState.storyboardCanvas` 字段，不新增数据库结构。

在类型层扩展为可选字段，保留现有字段原样：

```ts
type StoryboardCanvasState = {
  viewport: { x: number; y: number; zoom: number };
  shots: StoryboardCanvasShotRef[];
  notes: StoryboardCanvasNote[];
  schemaVersion?: 2;
  groups?: StoryboardCanvasGroup[];
  edges?: StoryboardCanvasEdge[];
};
```

兼容规则：

1. 读取旧数据时，缺失 `schemaVersion/groups/edges` 视为空集合，不迁移数据库。
2. `shots` 和 `notes` 仍是第一版的兼容主字段；新字段只增量保存布局能力。
3. 保存前统一执行 `normalizeStoryboardCanvas`：修正非法坐标、非法缩放、重复引用和无法解析的对象引用。
4. 归一化失败时降级为空布局并保留原始草稿，不阻断项目打开。
5. `ProductionWorkbench` 继续把 `storyboardCanvas` 放入原有草稿 payload，保证本地与云端路径一致。

## 6. 性能与稳定性

- 拖拽和缩放期间使用 `requestAnimationFrame` 合并视口更新，避免每个 pointer event 都触发完整保存。
- 交互中的布局变更只更新本地 React 状态，沿用现有 debounce/autosave；松开指针后再触发持久化。
- 对远离视口的对象进行轻量渲染裁剪，至少保留一个卡片尺寸的缓冲区，防止大画布对象数量增加后卡顿。
- 不在画布中重复加载图片；继续复用现有 `frames` URL 和浏览器缓存。
- 所有键盘操作检查焦点是否在输入框/contentEditable 内，避免删除便签文字时误删对象。
- 任何布局对象都不能导致页面横向溢出；无限只针对世界坐标，不把 DOM 尺寸无限撑大。

## 7. 实施分期

### Phase 1：无限视口与兼容层

- 扩展类型和归一化函数。
- 无限平移、指针中心缩放、适配视图。
- 保持旧镜头/便签行为和现有测试契约。

### Phase 2：导演整理能力

- 单选/多选/框选、键盘删除、批量移动。
- 分组框、连线、对齐/等距、按场次自动排版。
- 镜头卡打开入口和失效引用处理。

### Phase 3：导出与性能

- PNG/JSON 导出。
- rAF 更新、保存 debounce、视口裁剪。
- 长剧本数据集与浏览器验收。

### 后续扩展：Universe 画布

当 Universe 节点模型明确后，再把世界观、角色、场景、道具和剧本节点作为新的引用类型接入，不修改本阶段的分镜数据兼容约定。

## 8. 验收标准

- 旧版只含 `viewport/shots/notes` 的项目打开后布局、便签和镜头引用不变。
- 可从任意方向连续平移，缩放不会把视口锁在固定边界；指针下内容保持相对位置。
- “适配视图”能覆盖所有当前对象，空画布不会出现 NaN 或不可见状态。
- 多选移动、框选、移出画布不会删除源分镜或项目数据。
- 自动排版只改变布局；刷新后布局仍从现有草稿恢复。
- 分镜子视图、制作工作台顶部导航、全局侧边导航和数据库 schema 均不改变。
- 单元/契约测试通过，Playwright 至少覆盖打开画布、平移、缩放、添加便签、自动排版、刷新恢复和导出入口。

## 9. 回滚

本阶段无数据库 migration。若线上出现问题，回滚前端 commit 即可；旧数据仍符合原 `shots/notes/viewport` 结构，不需要数据回滚或清理。
