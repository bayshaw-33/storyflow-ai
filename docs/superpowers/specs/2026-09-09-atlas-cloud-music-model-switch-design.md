# 歌曲工作台 Atlas Cloud 音乐模型切换设计

**日期：** 2026-09-09

**状态：** 用户已确认设计方向，已移除 MiniMax Music 2.6，待书面规格复核

**范围：** 歌曲工作台的 Atlas Cloud 音乐模型选择、参数适配和生成验证

## 1. 目标

- 用户可以在歌曲工作台手动选择 Atlas Cloud 的音乐生成模型。
- 模型选择器只展示能生成音乐文件的模型，不展示 TTS、ASR 或其他语音模型。
- 第一批支持 `minimax/music-3.0`，并为 Atlas Cloud 已公开的其他音乐模型保留可扩展目录。
- 不改变现有歌词、翻译、曲风提示词、A/B 候选、历史、播放器和下载流程。
- 生成请求始终由服务端发送，API Key 不进入浏览器。

## 2. 非目标

- 本次不接入 TTS、声音克隆或语音转写。
- `minimax/lyrics-generation` 只生成歌词，不作为音乐模型出现在音乐生成选择器中。
- 不把模型切换扩展成用户自定义任意模型 ID；服务端维护允许的音乐模型目录。
- 不重新设计歌曲工作台的整体两栏结构，只在现有成果区补充清晰的模型选择和参数提示。

## 3. 交互设计

### 3.1 模型选择位置

在“音频候选/生成歌曲”区域标题行放置紧凑的“音乐模型”选择器，位于主要生成按钮之前。桌面端与标题、候选生成操作保持同一行；窄屏端自动换行，选择器和生成按钮各自保持可触达尺寸，不挤压歌词或曲风提示词。

选择器显示人类可读名称，提交值使用服务端目录中的完整模型 ID：

| 显示名称 | 模型 ID | 类型 |
| --- | --- | --- |
| MiniMax Music 3.0 | `minimax/music-3.0` | music |
| Suno Chirp v5 | `suno/chirp-v5` | music |

如果某个模型当前没有可用 Atlas Cloud 配置，不从页面伪造可用状态；选择器显示为不可用或接口返回明确的配置提示。默认模型为 `minimax/music-3.0`，若服务端目录没有该模型则回退到第一个可用音乐模型。

### 3.2 选择后的提示

- MiniMax 选中时显示：支持歌词、曲风提示词、纯音乐和 MP3/WAV 输出。
- Suno 选中时显示：使用当前歌词/风格内容，并按 Suno 参数规则提交。
- 切换模型只改变后续生成请求，不清空当前歌词、曲风提示词、候选结果或历史。
- 已经生成的候选保留原来的 provider/model 标识，不能因当前选择变化而被改写。

### 3.3 状态与错误

- 生成中锁定当前模型选择，避免同一批次出现不可解释的模型变化；完成或失败后恢复可切换。
- 切换模型不会自动生成，只有点击生成按钮才产生供应商任务和费用。
- 模型不可用、参数不支持、额度不足和供应商失败分别显示可理解的原因，并提供重试入口。
- 在页面刷新后恢复当前选中的模型；没有保存值时使用服务端默认值。

## 4. 服务端架构

### 4.1 允许目录

在音频能力层定义音乐模型目录，每项包含：`id`、显示名、provider、kind、默认参数和参数适配器。目录是服务端权威来源；客户端只消费经过筛选的 `kind: music` 能力数据。

现有 `AudioKind = "music" | "tts"` 继续保留，用于服务端门禁。能力接口可以同时保留 TTS 能力给配音工作台，但歌曲工作台只读取 `music` 过滤结果，绝不把 TTS 模型渲染到歌曲选择器。

### 4.2 Atlas Cloud 请求

所有 Atlas Cloud 音乐模型使用：

`POST https://api.atlascloud.ai/api/v1/model/generateAudio`

请求顶层包含 `model` 和该模型支持的字段。MiniMax Music 3.0 使用 `prompt`、可选 `lyrics`、`lyrics_optimizer`、`is_instrumental`、`format`、`sample_rate`、`bitrate` 等字段；Suno 使用自己的 `custom`、`instrumental`、`vocal_gender` 等字段。模型差异只存在于 adapter，不泄漏到页面组件。

Atlas Cloud 返回异步 prediction ID 后，复用现有音频任务轮询、结果入库、签名 URL、A/B 候选和播放器流程。

### 4.3 数据与安全

- 本地任务的 `provider` 固定为 `atlascloud`，`model` 保存完整模型 ID，便于历史追踪。
- API Key 仅从服务端环境或已授权的服务端连接读取。
- 客户端错误只显示安全错误码和可操作文案，不返回请求头、密钥或完整供应商响应。
- 幂等键必须包含 model，避免同一歌词在切换模型后错误复用旧任务。

## 5. 测试与验收

### 5.1 自动化测试

- 音乐模型目录只返回 `kind: music` 项，不返回 TTS/ASR。
- MiniMax Music 3.0 请求使用 Atlas Cloud endpoint、完整模型 ID和正确的顶层参数。
- Suno 请求使用对应 adapter，不误发 MiniMax 字段。
- 选择模型会进入批次和单任务请求，重试仍使用原候选的模型。
- 幂等键区分不同模型；切换模型不会复用旧模型的任务。
- 请求失败时歌词、曲风提示词和既有候选不被清空。

### 5.2 UI/UX 验证

- 1440px：模型选择器、生成按钮和状态信息同一操作区清晰排列。
- 1024px：无标题挤压、无横向溢出，模型名和状态可读。
- 390px：模型选择器与生成按钮自然换行，按钮触控区域不小于 44px。
- 生成中、成功、失败和不可用状态不改变成果区的整体结构。
- 当前候选始终显示真实 provider/model，避免用户误以为切换会改写历史结果。

### 5.3 真实 API 验证

- 使用 Atlas Cloud 有效服务端配置分别提交 MiniMax Music 3.0 和至少一个其他音乐模型。
- 验证返回任务被受理、轮询完成、音频成功入库、播放器可试听且可下载。
- 验证一次 TTS 模型不会出现在歌曲工作台选择器中，也不会被歌曲生成请求接受。
- 记录实际供应商响应状态；密钥、完整授权头和敏感信息不写入日志或报告。

## 6. 验收标准

用户可以在歌曲工作台手动选择不同 Atlas Cloud 音乐模型；选择器不出现 TTS/ASR；模型切换不丢失当前创作内容；不同模型请求参数正确适配；生成结果继续进入现有 A/B 候选、历史、播放器和下载链路；真实 API 至少成功生成一首音乐，失败时能明确区分配置、供应商和入库问题。
