# 剧本工作台精简与 KK 对话修复设计

日期：2026-08-21  
状态：用户已确认  
范围：统一制作工作台的剧本阶段、KK 剧本对话服务

## 目标

将剧本阶段恢复为安静、以 AI 对话为主导的两栏工作台，同时修复 production 中 KK 对话因会话 ID 非 UUID 而无法写入数据库的问题。

本次不修改剧本、Universe 或项目业务数据，不执行数据清理，也不引入数据库 migration。

## 已确认界面方案

采用方案 A“安静的 AI 对话台”。

### 顶部

- 保留项目名、Universe 状态、保存状态、剧本/美术/分镜/视频四阶段图标与“更多”。
- 保持全局左侧导航可见。
- 不增加新的外围导航或大型阶段标签。

### 左栏

- 保留世界观、角色圣经、剧情及大纲、分集计划、剧本正文的完整流程树。
- 雷同审查仍属于剧情及大纲阶段，不默认抢占当前步骤。
- 流程状态使用短标签，不重复显示教学说明。

### AI 对话主区

- 删除大幅欢迎语、宣传性介绍、“KK · AI 剧本伙伴”“对话优先”等重复标签。
- 顶部只显示一条紧凑的当前上下文，例如“世界观 · 尚未开始”。
- 新项目引导语作为 KK 的第一条对话消息出现，不使用独立 Hero。
- 对话记录占据主空间，输入框固定在底部。
- 当前文档、本土化、版本、证据、定稿与留痕按需打开，不长期占用主界面。

### 错误状态

- 错误提示显示在输入框上方，使用紧凑样式。
- 失败后保留用户输入、历史消息和候选修改。
- 重试必须复用同一输入和幂等快照。
- 面向用户显示可读错误和请求编号，不展示 Supabase 原始错误。

## KK 对话故障根因与修复

production 请求 `req_mt2kvfh3_bgwa3a` 的日志显示：前端提交的会话 ID 为 `kk-<work UUID>`，而 `storyflow_conversation_threads.id` 是 UUID 字段，Supabase 返回 `22P02 invalid input syntax for type uuid`。

修复规则：

1. 每个 Work 的默认剧本会话直接使用该 Work 的 UUID，保持稳定、可刷新恢复。
2. 服务端对 conversation ID 做 UUID 校验；旧客户端提交的 `kk-<work UUID>` 兼容归一为 Work UUID。
3. GET 历史、聊一聊、生成修改方案与雷同审查必须使用同一归一规则。
4. 非法且无法归一的值返回明确的 `validation_failed`，不得继续发送到 Supabase。

## 数据流

1. 工作台从 URL/上下文取得 Work UUID。
2. 客户端以 Work UUID 作为默认 conversation ID。
3. API 路由统一校验并归一 conversation ID。
4. 服务层读取或创建 thread，追加用户消息，调用模型，再追加助手消息。
5. 前端更新对话；失败时保留输入并展示紧凑错误提示。

## 验收标准

- production 中发送普通“聊一聊”不再触发 UUID `22P02`。
- 刷新页面后能恢复同一个 Work 的对话历史。
- “生成修改方案”和雷同审查使用相同有效会话。
- 剧本主区首屏不再出现大型欢迎 Hero 或重复说明。
- 桌面端维持两栏结构，AI 对话明显占据主要空间。
- 全局左侧导航、Universe 入口和四阶段切换保持可用。
- 现有剧本、项目、Universe 数据不受影响。
