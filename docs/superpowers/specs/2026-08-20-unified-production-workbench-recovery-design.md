# KIIKIS 统一制作工作台恢复设计

> 日期：2026-08-20  
> 状态：Mockup 已确认，待规格最终确认  
> 适用版本：KIIKIS V2.2  
> 核心目标：恢复同一项目内“剧本—美术—分镜—视频”的统一制作体验，并将 AI 对话型剧本创作正确嵌入其中。

## 1. 背景与问题

当前线上同时存在两套互相冲突的工作台结构：

1. 旧 `ProductionWorkbench` 已具备剧本、美术、分镜、动态分镜、视频的统一页面骨架。
2. V2.2 后续新增独立 `/script-workbench`，将剧本创作拆出制作工作台。
3. “动态分镜”仍作为独立顶级 Tab，与 V2.2 已确认的单一分镜阶段冲突。
4. 项目入口、工作身份、鉴权方式和数据库依赖未完全统一，造成跳转重复、项目上下文丢失、`Authentication required` 和 `Screenplay service unavailable`。
5. 独立剧本室叠加全局侧栏和内部流程栏，形成视觉上的三栏结构；当前文档又被放到对话区下方，导致 AI 对话空间不足、页面过长和大量空白。

本设计不做简单的旧代码回滚。目标是恢复旧制作台真正有效的统一切换，同时保留 V2.2 已完成的 AI 对话、不可变版本、候选审阅、Universe 和创作留痕能力。

## 2. 产品原则

1. **一个项目、一个制作工作台**：剧本、美术、分镜和视频必须共享 Project、Work、Universe 和版本关系。
2. **AI 对话主导剧本创作**：剧本 Tab 的主要空间属于 KK 对话，不退回复杂表单或三栏编辑器。
3. **Universe-first**：统一制作工作台不是单纯的视频流水线；每个阶段都可以读取、绑定和回流 Universe。
4. **允许探索，不静默覆盖**：用户可以跨阶段试做；AI、上游版本和 Universe 更新不得直接覆盖已存在内容。
5. **旧数据优先保护**：恢复过程中不删除现有项目、剧本、版本、资产、分镜、视频或 Universe 数据。
6. **看起来能点就必须可用**：所有 Tab、项目入口、保存、版本、导出和错误恢复操作必须有真实行为。

## 3. 信息架构

### 3.1 唯一制作工作台

顶级阶段固定为：

```text
剧本 → 美术 → 分镜 → 视频
```

- 不显示独立“动态分镜”顶级 Tab。
- 剪辑保持独立专业工作台，在视频阶段提供“进入剪辑”入口。
- 歌曲和配音保持独立 Work，通过显式使用关系关联项目、角色、场景或剪辑工程。
- 成果导出与创作留痕是横向能力，始终位于统一工作台顶部，不作为末端阶段。

### 3.2 顶部项目栏

统一项目栏始终显示：

- 返回项目管理。
- 当前项目名称与作品类型。
- 当前绑定的 Universe 与使用版本。
- 自动保存状态。
- 版本入口。
- 成果与留痕入口。
- 更多操作。

四个阶段的切换位于项目栏下方。切换阶段时不得整页跳转或重新创建项目。

## 4. 剧本 Tab

### 4.1 真正的两栏布局

进入统一制作工作台后，隐藏全局大侧栏，只保留工作台内部的返回入口，避免“全局导航 + 剧本流程 + 内容区”形成三栏。

剧本 Tab 只包含两列：

1. 左侧固定宽度流程栏，建议桌面端约 260–300px。
2. 右侧自适应主创作区，默认显示大型 AI 对话。

当前稿和版本对比通过右侧主区内的视图切换显示，不增加永久第三栏，也不放到对话区下方。

### 4.2 剧本流程

左侧流程固定为：

1. 世界观。
2. 角色圣经。
3. 剧情及大纲。
4. 分集计划。
5. 剧本正文。

其中前三项构成不可改变的剧本创作“三部曲”。

每个节点显示以下状态之一：

- 未开始。
- 创作中。
- 当前可用版本。
- 可能需要同步。
- 存在冲突。

“完成”统一解释为“用户确认当前可用版本”。用户确认后可以继续，也可以随时返回修改。上游修改只标记下游可能需要同步，不删除或强制重建下游内容。

### 4.3 AI 对话

右侧主区提供三个互斥视图：

- 对话。
- 当前稿。
- 版本对比。

默认进入“对话”。

对话必须满足：

1. 重开项目恢复完整历史消息。
2. 用户本轮输入必定进入本轮模型上下文。
3. “聊一聊”只讨论，不修改正文。
4. “生成修改方案”产生可逐块审阅的候选。
5. 只有用户主动采用后，候选才写入当前稿并生成新版本。
6. 每个候选记录来源消息、模型、任务、时间、目标范围和采用状态。
7. 用户可以指定整部、某集、某场或选中文字作为作用范围。
8. 长对话应使用虚拟列表或分页加载，输入框保持稳定可见。

### 4.4 当前稿与版本对比

“当前稿”在右侧主区内显示结构化文档，不与对话永久并排。

“版本对比”至少支持：

- 当前版本与候选版本并排对比。
- 定位到节点、集、场和文本区间。
- 逐块采用或拒绝。
- 冲突时不覆盖当前内容。

最终剧本导出遵循用户此前确认的剧本文件样本格式，不以通用 Markdown 代替正式格式。

### 4.5 本土化与雷同审查

- 不恢复“翻译”功能。
- 本土化作为左侧常驻工具，可以作用于世界观、角色、大纲、单集或正文。
- 雷同审查位于“剧情及大纲”内部，在确认大纲当前可用版本前执行。
- 雷同审查只提供辅助风险提示、对照范围和证据，不做法律裁定。

## 5. 美术 Tab

美术 Tab 在同一制作工作台壳内运行，不跳转到独立页面。

内部统一管理：

- 角色。
- 场景。
- 道具。

每个资产显示 Universe Entity、Asset Identity、当前 Asset Version、来源剧本版本和使用状态。嵌入模式必须按 Project/Work 作用域隔离本地草稿，禁止读取其他项目的全局美术草稿。

## 6. 分镜 Tab

分镜 Tab 合并原“分镜”和“动态分镜”概念，内部提供：

- 结构化镜头表。
- 每镜头 4/6/9/12 宫格。
- 动态运动预览。
- 视频模型提示词。
- 人工修改与锁定。
- 版本对比。
- 确定性导出。

已确认分镜可以直接进入视频阶段，不经过第二个同义顶级页面。

## 7. 视频 Tab

视频 Tab 只消费明确选定的分镜和提示词版本，至少提供：

- 按场和镜头查看生成任务。
- 生成中、待确认、已确认、失败和可重试状态。
- 重试时保留旧结果和历史版本。
- 正式结果转存持久化对象存储，不保存 Provider 临时 URL。
- 完成后进入剪辑工作台。

## 8. Universe、版本与留痕

### 8.1 Universe

顶部始终显示当前 Universe 状态：

- 未绑定。
- 已绑定及其版本。
- Universe 存在更新。
- 当前 Work 产生候选 Canon。

Work 可以独立开始，Universe 可以后续绑定。系统不得自动创建空 Universe，也不得静默把作品内容写入 Canon。

### 8.2 横向版本能力

剧本、美术、分镜和视频的正式产物都必须拥有不可变版本，并记录来源版本关系。阶段切换不改变身份，也不复制出新的平行项目。

### 8.3 成果与创作留痕

统一入口支持按当前阶段或整个项目导出：

- 定稿成果。
- 对话与生成记录。
- 候选、采用与拒绝记录。
- 版本与谱系。
- Universe 引用。
- 模型、任务和时间信息。
- Evidence Event 清单。

证据用于事实核验，不宣称法律裁定。

## 9. 路由与身份

### 9.1 规范入口

建议规范路由：

```text
/production?projectId=<projectId>&workId=<workId>&tab=<script|art|storyboard|video>&unitId=<optionalUnitId>
```

- `projectId` 和 `workId` 决定工作台身份。
- `unitId` 只用于定位某一集、场或制作单元，不得成为打开整个项目的硬性条件。
- `tab` 决定当前阶段，刷新后保持。

### 9.2 兼容入口

旧入口必须解析原参数后进入同一规范路由：

- `/script-workbench` → `tab=script`。
- `/production-workbench` → 保留原阶段或进入默认阶段。
- `/storyboard-workbench` → `tab=storyboard`。
- 旧动态分镜 URL → `tab=storyboard` 并保留目标 scene/shot。

兼容跳转必须保留可解析的 projectId、workId、sourceUnitId、episodeId、sceneId 和 handoff 信息。

## 10. 鉴权与服务恢复前置条件

统一工作台实施前必须先完成生产环境止血：

1. 浏览器页面、项目解析接口和剧本 API 使用同一 Supabase 会话来源。
2. Cookie 和 Bearer 兼容策略只能在统一鉴权适配层处理，页面不得各自实现一套会话判断。
3. 生产数据库缺失的剧本单元、版本、依赖、会话和候选表必须通过可审计 migration 补齐。
4. migration 只新增或修复结构，不删除现有项目和创作数据。
5. 服务错误必须区分未登录、数据库结构缺失、权限不足、网络失败和版本冲突，不再统一显示 `Screenplay service unavailable`。

## 11. 数据保护与迁移约束

1. 上线前只读盘点生产环境 Project、Work、剧本项目、Universe 和关键版本数量。
2. 数据库结构变更前生成备份或可恢复快照。
3. 禁止以清理小说数据为理由删除其他 Work 或 Project。
4. 旧项目首次打开时只做身份解析和兼容关联，不复制、不覆盖原内容。
5. 无法解析的旧项目进入“需要修复关联”状态，并提供明确恢复入口，不得从项目管理中消失。

## 12. 响应式行为

- 宽屏：固定左流程栏 + 大型 AI 主区。
- 中等屏：缩窄左栏，但继续保持两栏。
- 小屏：流程栏折叠为阶段选择区，主区保持单列。
- 任何尺寸下都不得同时显示全局大侧栏、内部流程栏和永久文档栏。

## 13. 验收标准

### 13.1 核心路径

1. 从首页“开始创作”、左侧“工作台”、项目管理和 Universe 打开同一项目时，均进入统一制作工作台。
2. 剧本、美术、分镜、视频切换不整页刷新，不丢失项目、Work、Universe、当前集或未提交输入。
3. `/script-workbench`、`/production-workbench` 和 `/storyboard-workbench` 旧链接仍能打开正确项目和阶段。
4. 不再显示独立“动态分镜”顶级入口。

### 13.2 剧本体验

1. 桌面端只有流程栏和 AI 主区两列。
2. 默认显示大型 AI 对话区，不显示欢迎页式大空白。
3. 重开项目恢复全部真实对话。
4. 当前输入影响本轮生成。
5. 候选未经采用不得修改当前稿。
6. 三部曲状态、雷同审查、本土化和正式剧本格式均可用。

### 13.3 数据与稳定性

1. 现有真实剧本项目仍可见、可打开、可继续创作。
2. 四个阶段使用同一 Project 和 Work 身份。
3. 不出现 `Authentication required`、缺表导致的 503 或无说明的通用服务错误。
4. 刷新、返回、跨 Tab 和重新登录后状态可恢复。
5. 使用至少一个真实长剧本项目完成剧本→美术→分镜→视频的端到端验证。

## 14. 发布与回滚

实施按以下顺序发布：

1. 生产数据只读盘点与备份。
2. 鉴权统一和数据库 migration。
3. 统一路由适配。
4. 统一制作工作台壳。
5. AI 剧本嵌入。
6. 分镜概念合并。
7. 真实项目与长剧本验证。
8. 生产发布后在线核验。

回滚必须以代码版本和向后兼容 migration 为单位，不通过删除生产数据回滚。旧项目兼容解析至少保留一个完整版本周期。

## 15. Mockup 已确认边界

用户已于 2026-08-20 确认以下 Mockup 方向：

- 顶部固定四阶段切换。
- 剧本采用真两栏布局。
- 右侧以大型 AI 对话为主。
- 当前稿和版本对比在主区内切换。
- Universe、成果与留痕始终可见。
- 美术、分镜和视频保持同一项目壳内切换。
