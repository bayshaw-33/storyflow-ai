# 创作工作台正文恢复与定稿回退设计

## 目标

修复小说版和剧本版在登录、换设备后无法直接看到已生成正文的问题，并补齐定稿后的可逆编辑流程。用户重新打开项目时应自动进入最近生成或修改的章节/集正文；取消定稿并修改后，保留原内容与版本历史，同时让当前阶段及所有下游阶段回到草稿，重新生成或定稿后才能继续。

## 范围

- 复用现有 `creationWorkspace` 云端项目 JSON，不新增数据库表或迁移。
- 在工作区设置中持久化最近使用的模式、视图和正文单元 ID。
- 对已有项目兼容：缺少恢复元数据时按最近 `updatedAt` 且有正文内容的单元回退。
- 基座文档、分集规划、正文单元和剧本场次的状态操作保持现有数据结构；新增显式取消定稿入口。
- 删除正文区重复的“AI 生成”按钮和顶部“创作流程”菜单，不删除底层 AI 能力或小说/剧本数据。
- 剧本模式的用户可见术语统一为“集”；小说模式继续使用“章/卷”语义。

## 状态与数据流

### 最近位置

扩展 `CreationWorkspaceV2.settings`，增加可选的恢复字段：

- `lastMode`: `novel | screenplay`
- `lastView`: 当前工作台视图
- `lastUnitId`: 最近正文单元 ID
- `lastUnitUpdatedAt`: 记录位置时的时间戳

切换模式、切换正文视图/单元、正文生成成功、正文编辑成功时更新这些字段，并走现有 localStorage + Supabase 保存路径。加载后先使用仍然存在且有权限的 `lastMode/lastUnitId`；无效或缺失时选择最近 `updatedAt` 的非空正文单元；都不存在时保持现有创作基座起始页。

### 定稿回退

- 基座文档和分集规划：已定稿时按钮显示“取消定稿并修改”；点击后立即将自身设为草稿，并按现有上游规则将所有下游文档、分集规划、正文单元和场次设为草稿。
- 正文单元：已定稿时提供“取消定稿并修改”；点击后仅将当前单元设为草稿，保留正文、版本历史、翻译和本土化内容。
- 剧本场次：保留已有逐场取消定稿行为；取消某场时所属集为草稿，不自动清空其它场次内容。
- 草稿状态下的编辑/生成沿用现有保存和版本机制；重新定稿前，下一阶段门禁继续阻止前进。

## UI 调整

- 删除顶部“创作流程”下拉入口。
- 删除正文区顶部重复的“AI 生成”按钮；AI 面板中的生成入口保留。
- 保留模式切换和正文目录，因为小说版与剧本版仍是独立内容。
- 定稿按钮根据状态显示“定稿”或“取消定稿并修改”。
- 所有剧本版标题、选择器、提示和生成反馈使用“第 N 集/集”；小说版使用“第 N 章”，卷仅用于小说版卷分组。

## 错误处理

- 恢复位置引用不存在的单元时不阻断页面加载，使用回退策略并将新位置保存。
- 云端保存失败时沿用现有“已保存到本地，云端同步暂时不可用”提示。
- 取消定稿不删除内容；只有原有显式删除操作才允许删除。

## 验证标准

1. 小说版和剧本版生成正文后，刷新或在另一浏览器登录同一项目，自动打开最近正文，且正文文本/结构化场次可见。
2. 基座文档或分集规划定稿后可取消定稿；编辑后自身及下游状态为草稿，未重新定稿时下一阶段不可进入。
3. 正文单元定稿后可取消定稿并编辑，内容与版本历史保留，重新定稿后制作/导出门禁恢复。
4. 页面不再显示顶部“创作流程”和正文区重复“AI 生成”；AI 面板仍可生成。
5. 剧本模式所有相关文案显示“集”，小说模式不受影响。
6. 现有创建工作台状态、解析器和 Supabase 同步测试保持通过，并新增恢复与级联回退测试。
